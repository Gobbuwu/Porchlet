## Decisions

- [0001](../adr/0001-supabase-over-firebase.md) Supabase over Firebase
- [0002](../adr/0002-frontend-stack-nextjs.md) Next.js, with the stack test's measurements (Gobbu kept Next.js after seeing them)
- [0003](../adr/0003-licence-mit.md) MIT
- [0004](../adr/0004-rls-is-the-only-gate.md) RLS is the only gate
- [0005](../adr/0005-secret-key-two-server-routes.md) Secret key in two server routes only
- [0011](../adr/0011-owasp-asvs-level-2.md) OWASP ASVS 5.0.0 Level 2
- [0012](../adr/0012-ci-pipeline.md) CI pipeline: jobs, tools (CodeQL and Semgrep, npm audit and OSV-Scanner, gitleaks, Dependabot), lockdown
- Dependencies: exact versions (`.npmrc` `save-exact=true`), and the newest release that is at least 7 days old when added, so a just-published compromised release is less likely to land. Tailwind is left out until M1 builds UI.
- Grant defaults (PR 2): the design doc's `alter default privileges in schema public revoke execute on functions from public` does nothing, because PUBLIC's execute on new functions is a global default and Postgres can't revoke a global default per schema. pgTAP failed on it (tests 14 and 15). The migration revokes it globally for `postgres` instead, so every function a migration creates starts with no execute grant and each migration grants execute explicitly. The design doc's section 3 needs the same fix.
- `.npmrc` sets `min-release-age=7` (PR 2, from a Semgrep finding), so npm 11.10 and later refuse releases younger than 7 days. npm 10, which Node 22 ships, reads the setting but doesn't enforce it, so the 7-day rule stays a manual check on Node 22.
- DCO sign-off uses Gobbu's GitHub noreply address (`347100038+Gobbuwu@users.noreply.github.com`), Gobbu's choice, so no personal email is published in commits.

## Threat model (repo and pipeline)

| Threat | Control | Where |
|---|---|---|
| Secret committed to git | `.env*` ignored except `.env.example`; GitHub secret scanning and push protection on; gitleaks (with a Supabase secret-key rule and a canary) on the full history in CI | `.gitignore`, repo settings, PR 2 |
| Secret key shipped to browsers | Grep `.next/static` for `sb_secret_` in CI, on all three Node versions | PR 2 |
| Malicious or vulnerable dependency | Exact pins, lockfile, 7-day age rule (`min-release-age`, Dependabot cooldown), review note per new dependency, npm audit, registry signatures, OSV-Scanner, Dependabot security updates | PR 1, PR 2 |
| Compromised CI workflow or action | `permissions: {}` by default, actions pinned by commit SHA, binaries by checksum, images by digest, `persist-credentials: false`, no secrets in CI, CodeQL and Semgrep scan the workflows | PR 2 |
| A new table or function open to `anon` by default | Default-privilege revokes in the first migration; pgTAP creates a probe table and function and checks `anon` and `authenticated` get nothing; RLS-on test for every public table | PR 2 |
| Unreviewed change reaching `main` | Ruleset: PR required, required checks, no force pushes, linear history | After PR 2 |
| Commit without sign-off | DCO check script with a self-test | PR 2 |
| A check that silently checks nothing | Count cross-checks: pgTAP files and tests run vs on disk, tables vs `-- Covers:` lines, gitleaks commits vs git, OSV packages vs lockfile, DCO commits vs GitHub's count; canary for gitleaks; self-test for DCO | PR 2 |

## Ruleset on `main` (Gobbu)

Add it before merging PR 2, so PR 2 is the first PR it gates. Repo → **Settings** → **Rules** → **Rulesets** → **New ruleset** → **New branch ruleset**:

1. **Ruleset name**: `main`. **Enforcement status**: Active. Leave the bypass list empty.
2. **Target branches** → **Add target** → **Include default branch**.
3. Tick **Restrict deletions** and **Block force pushes**.
4. Tick **Require linear history**.
5. Tick **Require a pull request before merging**: **Required approvals 0** (GitHub doesn't let a PR's author approve it). Under allowed merge methods, keep only **Squash**.
6. Tick **Require status checks to pass**, tick **Require branches to be up to date before merging**, then **Add checks** and add each of these 14, picking **GitHub Actions** as the source when asked (so another app can't post a check with the same name):
   - `DCO sign-off`
   - `Lint and types`
   - `Build (Node 22)`, `Build (Node 24)`, `Build (Node 26)`
   - `Database tests`
   - `E2E (chromium)`, `E2E (firefox)`, `E2E (webkit)`
   - `Secret scan`
   - `Dependency scan`
   - `SAST (CodeQL, javascript-typescript)`, `SAST (CodeQL, actions)`
   - `SAST (Semgrep)`
7. Tick **Require code scanning results** → add tool **CodeQL**, alerts **Errors**, security alerts **High or higher**. If that rule isn't offered, add `CodeQL` to the status checks in step 6 instead.
8. **Create**. PR 2 should then show the checks as required and still be mergeable.

- **gitleaks and Supabase's documented key format.** Supabase documents secret keys as `sb_secret_<22-char-random>_<8-char-checksum>` ([self-hosted auth keys](https://supabase.com/docs/guides/self-hosting/self-hosted-auth-keys)). PR 3's canary now plants a fresh fake key in exactly that shape on every run, alone on a line, and fails unless gitleaks reports it under `supabase-secret-key`. The docs don't name the character set; the canary uses `[A-Za-z0-9]`, and the rule also allows `_` and `-` (**unverified** against a real key).

## Gaps

- Dependabot doesn't cover the Semgrep image pinned in the `semgrep` job's `container:`. Bump it by hand (new digest, at least 7 days old) when Dependabot bumps the other actions, or at least monthly.
- E2E covers only the home page and `/api/health`, and runs on Node 22 only. It doesn't start Supabase yet; M1 adds that with the auth flow.
- Semgrep's registry rule packs are fetched at run time, not pinned, so results can change without a commit.
- Playwright downloads browsers from Microsoft's CDN; we don't pin their checksums.
- `npm audit signatures` failed three times (cec6e39, 56c6867, 0d57500 on 2026-11-23) with `EMISSINGSIGNATUREKEY: napi-postinstall@0.3.8 has attestations but no corresponding public key(s) can be found`, and passed on other runs with the same lockfile. **Root cause (verified from the run's diagnostics):** npm's CDN edge in Portland (`cf-ray …-PDX`, `cf-cache-status: HIT`, `age: 1792463`) serves a copy of that package's attestations saved at 01:26:15 UTC on 2026-11-03, 14 s after publish, holding only the SLSA provenance (no keyid) and not the npm publish attestation. The Chicago edge serves a copy saved at 01:27:44 that holds both. The cache lifetime is one year (`max-age=31557600`), so runners routed through that edge fail every time. Our check is right to fail: npm cannot verify the publish signature it was given. Workaround: `overrides` pins `napi-postinstall` to 0.3.7 (published 2026-10-22, within `unrs-resolver`'s `^0.3.7`, dev-only, used by the ESLint import resolver). Remove the override once npm purges the stale copy (not yet reported to npm). Any other package can hit the same CDN race; the step now prints the failing package's attestations, npm's TUF keys and the registry keys API on failure, so it is diagnosable in one run.
- E2E installs browser system packages from the Ubuntu apt mirror on every run (`--with-deps`), so a slow mirror makes E2E slow or time out (it did once, run 45214507704). A Playwright container image pinned by digest would remove this; not done in M0.
- ESLint 9 is unsupported upstream; blocked on `eslint-config-next` allowing 10.
- Merge commits are not checked by the DCO script or by gitleaks (git shows no patch for them). gitleaks also skips commits that only delete lines, which have nothing to scan; the cross-check counts the same way. The first run after the round C revert (a delete-only commit) failed the old cross-check, 12 scanned vs 13, which is how this was found. Squash merge only, so `main` gets one commit per PR, and every PR commit is checked.
- The planted round A Vercel preview (b03a832) contains the planted `eval` of the URL hash. It has no data or secrets, and later commits replace the branch preview.
- The spike's source is archived in the project files (`porchlet-m0/stack-spike-src.tar.gz`), not in the repo.
