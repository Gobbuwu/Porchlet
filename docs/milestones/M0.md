## Decisions

- [0001](../adr/0001-supabase-over-firebase.md) Supabase over Firebase
- [0002](../adr/0002-frontend-stack-nextjs.md) Next.js, with the stack test's measurements (Gobbu kept Next.js after seeing them)
- [0003](../adr/0003-licence-mit.md) MIT
- [0004](../adr/0004-rls-is-the-only-gate.md) RLS is the only gate
- [0005](../adr/0005-secret-key-two-server-routes.md) Secret key in two server routes only
- [0011](../adr/0011-owasp-asvs-level-2.md) OWASP ASVS 5.0.0 Level 2
- Dependencies: exact versions (`.npmrc` `save-exact=true`), and the newest release that is at least 7 days old when added, so a just-published compromised release is less likely to land. Tailwind is left out until M1 builds UI.
- DCO sign-off uses Gobbu's GitHub noreply address (`347100038+Gobbuwu@users.noreply.github.com`), Gobbu's choice, so no personal email is published in commits.

## Threat model (repo and pipeline)

| Threat | Control | Where |
|---|---|---|
| Secret committed to git | `.env*` ignored except `.env.example`; GitHub secret scanning and push protection on; gitleaks on diff and history in CI | `.gitignore`, repo settings, PR 2 |
| Secret key shipped to browsers | Grep `.next/static` for `sb_secret_` in CI | PR 2 |
| Malicious or vulnerable dependency | Exact pins, lockfile, 7-day age rule, review note per new dependency, dependency scan in CI, Dependabot security updates | This PR, PR 2 |
| Compromised CI workflow or action | `permissions: contents: read` by default, actions pinned by commit SHA, no long-lived cloud secrets in CI | PR 2 |
| Unreviewed change reaching `main` | Ruleset: PR required, required checks, no force pushes, linear history | After PR 2 |
| Commit without sign-off | DCO check script | PR 2 |

## How it was verified

Environment for everything below: Linux 6.18 x86_64 cloud container, 4 vCPU, 15 GB RAM, Node 22.23.5, npm 10.9.9, Docker 29.10.0.

| Check | Command | Result |
|---|---|---|
| Repo settings | `gh api repos/Gobbuwu/porchlet` and `.../private-vulnerability-reporting` | Public; squash merge only (`allow_merge_commit` and `allow_rebase_merge` false); `delete_branch_on_merge` true; secret scanning and push protection enabled; Dependabot security updates enabled; private vulnerability reporting enabled. The Dependabot alerts endpoint is blocked by this session's proxy (HTTP 403), but security updates can't be on without alerts. |
| `supabase start` in a cloud session | `npx supabase start` (CLI 3.3.0, spike) | First run failed after 98 s: image blobs on `pkg-containers.githubusercontent.com` are blocked by this session's proxy, and the Docker Hub fallback returned HTTP 429. The second run, with the images now cached, succeeded in 67 s. Postgres 17.12, auth health 200. GitHub Actions has no such proxy, so CI is not affected (to confirm in PR 2). |
| `supabase start` with the pinned CLI | `npx supabase start` (CLI 3.1.0, this repo) | Succeeded in one run of 103 s, including pulling this version's images. The CLI retried on its own after the same proxy blocks (27 "Forbidden" lines in the log, no 429s this time). Postgres 17.11, auth health 200. |
| Stack test | See ADR 0002 | All three stacks passed the same Playwright check |
| Lint | `npm run lint` | 0 problems |
| Types | `npm run typecheck` | 0 errors |
| Build | `npm run build` | Passes in about 7 s; routes `/`, `/_not-found`, `/api/health` |
| Dependencies | `npm audit` | 0 vulnerabilities |
| Vercel preview (first try) | Vercel build of f4f20c1 | Failed. `next build` succeeded, then Vercel stopped with `[STATIC_BUILD_NO_OUT_DIR] No Output Directory named "public"`: the project was created on the empty repo, so its Framework Preset is "Other".
